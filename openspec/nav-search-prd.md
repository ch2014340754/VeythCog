## 1. 背景与现状

### 1.1 背景

导航页已经具备 7 个分类、267 条书签、S3 图标资产与分类切换能力，整体可用。当前搜索仍是最基础形态：

- 输入关键词；
- 选择百度 / Google / Bing；
- 回车或点击放大镜后 `window.open` 对应搜索引擎结果页。

用户希望搜索框从“跳转搜索引擎”升级为“先给信息、再决定去哪搜”：

1. 输入时给出**联想建议**，减少完整输入成本；
2. 在联想面板**首行展示翻译**，解决中英混合查询与跨语言检索；
3. 提供**可选 AI 回答**，并允许用户选择是否优先查个人知识库。

### 1.2 现状代码与接口

| 位置 | 现状 | 对本需求的影响 |
|---|---|---|
| `VeythCog-V/src/pages/Home/SearchBar.tsx` | 搜索引擎下拉、输入框、回车 / 放大镜 `window.open`；`maxWidth: 640`；无联想、翻译、AI | 本需求的核心改造对象 |
| `VeythCog-V/src/stores/navStore.ts` | `searchEngine: 'baidu' \| 'google' \| 'bing'`，已持久化 | 保留搜索引擎选择，新增搜索偏好 |
| `VeythCog-V/src/api/chat.ts` | `streamChatMessage` 支持 `message / vendor / modelCode / conversationId / docIds`；SSE 先 `references`，再 token，末尾 `[DONE]`，可中断 | AI 回答可复用 SSE 解析与中断能力 |
| `ChatController#/chat/stream` | 请求带 `docIds` 才调用 `RagChatOrchestrator.retrieveSafely` | 当前没有“全知识库优先”模式 |
| `RagChatOrchestrator` | `docIds` 为空直接返回空引用；有 `docIds` 才检索 | 需要新增 `knowledgeScope=ALL` 或等价开关 |
| `knowledge-prd.md` | RAG 检索与引用由后端统一产出，前端只消费 `references` | 新 PRD 继续沿用该口径 |

### 1.3 关键结论

- **不能只靠前端传空 / 非空 `docIds` 表达“是否优先知识库”**。空 `docIds` 在现有实现中等价于“不查知识库”，无法表达“查全库但允许回退”。
- AI 回答应**复用现有流式能力**，但不建议直接写入普通对话历史，避免每次搜索都在会话列表里产生垃圾会话。
- 输入联想与翻译都属于**高频、低价值单次请求**，必须有防抖、取消、缓存和超时降级，不能阻塞主搜索。

## 2. 目标与非目标

### 2.1 目标

1. 用户输入 2 个字符后，300ms 内看到可点击的联想建议；
2. 联想面板首行展示查询翻译，支持一键用译文搜索；
3. 用户可主动触发 AI 回答，回答流式输出，并可选择“优先知识库”；
4. 原有“回车跳转搜索引擎”的行为保持不变，新增能力不打断旧习惯；
5. 所有新增能力失败时静默降级，搜索框始终可用。

### 2.2 非目标（本期不做）

- ❌ 不做完整搜索结果聚合页、新闻 / 图片 / 视频垂直搜索；
- ❌ 不做实时网页抓取或联网事实核查；AI 回答仅基于模型与个人知识库；
- ❌ 不做搜索框内多轮对话；需要追问时跳转 AI 对话页；
- ❌ 不做模型选择器；搜索 AI 使用当前账号默认模型；
- ❌ 不做跨用户知识库检索与权限改造；
- ❌ 不做搜索词广告、竞价或商业化。

### 3.1 目标用户

- 主要用户：单账号自用的 VeythCog 用户；
- 使用场景：打开新标签页后，快速查资料、查自己的笔记、决定用哪个搜索引擎。

### 3.2 核心用户故事

## 4. 核心体验

### 4.1 交互总览

```
┌──────────────────────────────────────────────────────────┐
│ [百度 ▾]  输入搜索内容                          [🔍]     │
└──────────────────────────────────────────────────────────┘
┌──────────────────────────────────────────────────────────┐
│ 译  Spring Boot 是一个用于构建独立应用的框架   [中→英]   │  ← 首行翻译
├──────────────────────────────────────────────────────────┤
│ 🔎 spring boot 面试题                                     │
│ 🔎 spring boot 自动配置原理                               │
│ 🔖 Spring 官方文档                                        │
│ 🕘 上次搜索：spring boot actuator                         │
├──────────────────────────────────────────────────────────┤
│ ✨ AI 回答    [ 优先知识库 ○ ]              Ctrl+Enter     │
└──────────────────────────────────────────────────────────┘
```

### 4.2 主流程

1. 用户聚焦搜索框并输入；
2. 输入长度 ≥ 2 且非纯符号 / URL 时，展开联想面板；
3. 面板首行异步请求翻译，翻译未返回时先展示联想，不阻塞；
4. 用户按 ↑ / ↓ 选择联想项，按 Enter 用选中词执行网页搜索；
5. 用户按 `Ctrl/Cmd + Enter` 或点击「AI 回答」，面板切换为 AI 回答态；
6. AI 以流式输出；若开启「优先知识库」，先检索个人知识库，再注入上下文；
7. 用户按 Esc 或点击面板外关闭；再次输入重新回到联想态。

### 4.3 关键原则

- **搜索优先**：默认 Enter 仍然是网页搜索，AI 回答必须由用户主动触发；
- **不阻塞**：翻译、联想、AI 任一失败都不影响输入与网页搜索；
- **可中断**：AI 生成过程中关闭面板或再次输入，立即 abort 请求；
- **不污染**：搜索 AI 不创建对话、不写对话历史；继续追问才进入正式对话。

## 5. 功能需求

### 5.1 输入联想

#### 5.1.1 触发规则

| 条件 | 行为 |
|---|---|
| 输入长度 < 2 | 不展开面板 |
| 输入为纯空格 / 纯符号 | 不展开 |
| 输入为合法 URL | 展示「打开网址」快捷项，不请求联想 |
| 输入法组合中（IME composing） | 不触发请求，不响应 Enter |
| 输入变化 | 300ms 防抖；新请求发出前 abort 旧请求 |
| 面板已打开且继续输入 | 保持面板，展示 loading 细状态，不清空旧建议 |

#### 5.1.2 联想来源与排序

本期（P0）同时做本地联想与搜索引擎远端 suggest，二者合并展示；本地结果必须先返回，远端结果到达后增量替换，远端失败不影响本地结果。

**本地联想**（零网络依赖，先返回）：

1. **最近搜索**：本地最近 20 条，前缀 / 包含匹配优先；
2. **导航书签**：267 条书签的标题与域名，标题前缀匹配权重最高；
3. **本地高频词**：同一 query 被搜索次数越多，排序越靠前；
4. 去重后最多展示 6 条，超出不展示。

**远端 suggest**（本期接入，作为增量增强）：

- 后端代理百度 / Google / Bing 的 suggest 接口，避免前端跨域；
- 超时 300ms，失败直接只用本地结果；
- 远端结果与本地结果合并，本地书签 / 历史优先，远端补充；
- 缓存 5 分钟，key 为 `engine + 归一化 query`；
- 远端结果到达前，面板先展示本地结果，不出现空白等待。

#### 5.1.3 展示规则

- 每条包含：类型图标、建议文本、来源标签（书签 / 历史 / 推荐）；
- 匹配片段高亮，但不高亮整行；
- 鼠标悬停与键盘选中使用同一套高亮样式；
- 点击建议：把建议文本填入输入框，并立即执行当前搜索引擎搜索；
- 若建议来自书签，右侧提供「打开书签」次级动作，点击直接打开书签 URL，不执行搜索。

#### 5.1.4 异常与空态

- 无建议：不展示空面板，保留翻译行与 AI 入口；
- 请求失败：静默隐藏联想区，不弹错误提示；
- 本地无历史：仅展示书签匹配，不展示“暂无历史”。

---

### 5.2 首行翻译

> 已确认：“首行翻译”= **联想面板第一行展示当前输入内容的翻译**，不翻译搜索结果；目标语言以中英互译为主。

#### 5.2.1 触发与语言

| 条件 | 行为 |
|---|---|
| 输入长度 2–80 | 触发翻译 |
| 输入为 URL / 邮箱 / 纯代码 | 不翻译 |
| 中文占比 ≥ 30% | 目标语言：英文 |
| 中文占比 < 30% | 目标语言：中文 |
| 输入已包含目标语言且无明显外语 | 不展示翻译行 |
| AI 回答态 | 隐藏翻译行，给回答留空间 |

#### 5.2.2 交互

- 首行结构：`译` 标签 + 译文 + 语言方向 + `复制` + `用译文搜索`；
- 翻译结果最多展示 2 行，超出省略；悬停可查看全文；
- 点击「复制」复制译文，toast 轻提示；
- 点击「用译文搜索」：把译文写入输入框，并按当前搜索引擎执行搜索；
- 翻译加载中展示细 shimmer，不改变面板高度；
- 翻译失败 / 超时：整行隐藏，不展示错误。

#### 5.2.3 性能与缓存

- 输入停止 600ms 后请求；
- 新输入立即 abort 上一次翻译；
- 后端缓存 24 小时，key 为 `归一化文本 + 目标语言`；
- 超时 1.5s；超时后本次不重试，下一次输入再试；
- 翻译请求不得阻塞联想与 AI 按钮。

#### 5.2.4 实现建议

- 新增 `POST /search/translate`，由后端统一调用翻译模型，避免前端暴露模型 Key；
- 翻译模型与对话模型解耦，优先使用轻量模型；若暂时没有独立翻译模型，可复用默认模型但限制输出长度；
- 返回 `{ sourceLang, targetLang, translatedText, cached }`；
- 不把翻译内容写入任何对话历史。

### 5.3 AI 回答

#### 5.3.1 触发方式

- 点击面板底部「AI 回答」；
- 或按 `Ctrl/Cmd + Enter`；
- 默认 Enter 不触发 AI，避免改变原有搜索习惯；
- AI 回答态下再次按 `Ctrl/Cmd + Enter` 不重复发起，按钮进入 loading。

#### 5.3.2 回答形态

- 在搜索框下方展开 **AI 回答卡片**，不跳转新页面；
- 流式输出 Markdown，面板最大高度 420px，内部滚动；
- 回答结构建议：
  1. 一句话结论；
  2. 3–5 条要点；
  3. 必要时给出处 / 引用；
  4. 末尾标注「AI 生成，请注意核实」；
- 回答完成后底部提供：
  - `重新生成`；
  - `继续追问`：跳转 `/chat`，新建会话并预填当前问题；
  - `复制`。

#### 5.3.3 模型与提示词

- 使用当前账号默认模型绑定（`vendor + modelCode`），搜索框不提供模型切换；
- 系统提示词约束：
  - 先给结论，再给理由；
  - 不确定时明确说明，不编造来源；
  - 不输出与问题无关的长篇背景；
  - 有知识库引用时使用 `[1]` `[2]` 标注；
- 无知识库引用时，不展示“参考来源”，只展示 AI 生成提示。

#### 5.3.4 知识库优先

面板底部提供开关：`优先知识库`。

| 状态 | 行为 |
|---|---|
| 关闭（默认） | 不检索知识库，直接普通 AI 回答 |
| 开启 | 先检索当前账号全部已向量化文档，命中则注入上下文；未命中则回退普通回答，并明确标注「知识库未命中，以下为通用回答」 |
| 检索失败 / 超时 | 回退普通回答，不阻塞；记录后端日志 |
| 无已向量化文档 | 开关置灰，提示「暂无已向量化文档」，不发起检索 |

- 开关状态持久化到本地 `veythcog:search:kb-first`，默认 `false`；
- **本期确认：只做全库检索，不做“只查选中文档”的二级选择**；后续如需要再复用知识库选择抽屉；
- 检索 topN 沿用知识库配置（默认 5），rerank 沿用现有策略；
- 引用展示为可点击 chip：文档标题 + 片段序号，点击打开对应知识库文档。

#### 5.3.5 后端模式要求

现有 `/chat/stream` 只有传 `docIds` 才检索，无法表达“全库优先 + 可回退”。本期按 **方案 A** 落地，方案 B 仅作为兼容备选保留。

**方案 A（本期采用）**：新增 `POST /search/ai/stream`

```json
{
  "query": "spring boot 自动配置原理",
  "knowledgeFirst": true
}
```

- 后端内部调用 `RagChatOrchestrator`，新增 `retrieveAllSafely(userId, query)`；
- 全库检索仅取当前账号下 `is_vectorized=true` 的文档；
- SSE 事件：`meta`（模型名 / 是否命中知识库）→ `references` → `delta` → `done`；
- 不创建 `conversationId`，不写对话历史。

**方案 B**：扩展 `/chat/stream`

- 增加 `knowledgeScope: 'none' | 'all' | 'selected'`；
- `selected` 时继续使用 `docIds`；
- `all` 时忽略 `docIds`，检索全部已向量化文档；
- 需要兼容旧客户端：未传 `knowledgeScope` 时保持现有行为。

> 产品侧优先选方案 A：搜索 AI 与正式对话的生命周期、历史策略不同，独立接口更容易控制“不污染会话列表”。

#### 5.3.6 异常与降级

| 场景 | 表现 |
|---|---|
| 模型超时 / 失败 | 卡片内展示「回答失败，重试」，保留问题 |
| 知识库检索失败 | 继续普通回答，卡片顶部提示「知识库检索失败，已使用通用回答」 |
| 用户关闭面板 | abort 流式请求，不保留半截回答 |
| 用户重新输入 | 关闭 AI 回答态，回到联想态；旧回答不保留 |
| 限流 | 提示「请求过于频繁，请稍后再试」，不自动重试 |

## 6. 页面状态与视觉

### 6.1 面板状态机

```text
IDLE
  └─ 输入 ≥2 ──> SUGGEST_LOADING
                    ├─ 有结果 ──> SUGGEST_READY
                    └─ 无结果 ──> SUGGEST_EMPTY（仅翻译 + AI 入口）
SUGGEST_READY
  ├─ 点击建议 / Enter ──> 执行网页搜索，关闭面板
  ├─ Ctrl+Enter / 点击 AI ──> AI_LOADING
  └─ Esc / 点击外部 ──> IDLE
AI_LOADING
  ├─ 首 token ──> AI_STREAMING
  ├─ 失败 ──> AI_ERROR（可重试）
  └─ 关闭 ──> abort，回 IDLE
AI_STREAMING
  ├─ done ──> AI_DONE
  └─ 关闭 / 重新输入 ──> abort，回 IDLE
```

### 6.2 视觉约束

- 面板宽度与搜索框一致，圆角 16px，沿用现有壁纸 / 主题玻璃体系；
- 最大高度 420px，超出内部滚动；
- 壁纸模式使用深色玻璃，主题模式使用亮色磨砂；
- 面板不应遮挡搜索框，定位为 `top: calc(100% + 8px)`；
- 移动端 / 窄屏：面板宽度 `calc(100vw - 32px)`，最大高度 60vh；
- AI 回答区与联想区切换时保持面板高度稳定，避免页面跳动。

## 8. 非功能要求

| 维度 | 要求 |
|---|---|
| 首屏 | 搜索框不因新增能力增加首屏请求；联想 / 翻译均按输入触发 |

## 10. 验收标准

### 10.1 输入联想

1. 输入 `s` 不展开；输入 `sp` 展开面板；
2. 输入 `spring` 后 300ms 内出现至少 1 条书签或历史建议；
3. 输入新字符时旧请求被取消，不出现旧结果覆盖新结果；
4. ↑ / ↓ 可切换选中项，Enter 用选中项搜索；
5. 点击书签建议旁的「打开书签」直接打开 URL，不执行搜索；
6. 无建议时不展示空面板，不出现“暂无数据”占位；
7. 中文输入法组合中按 Enter 不会误触发搜索；
8. 远端 suggest 失败时仍展示本地书签 / 历史结果，不出现错误提示；
9. 远端结果晚到时只追加 / 替换远端段，不覆盖用户已选中的高亮项。

### 10.2 首行翻译

1. 输入中文“自动配置原理”，首行展示英文译文；
2. 输入英文“spring boot auto configuration”，首行展示中文译文；
3. 点击「用译文搜索」，输入框变为译文并执行当前引擎搜索；
4. 点击「复制」复制译文，出现轻提示；
5. 翻译接口超时 / 失败时整行隐藏，联想与搜索不受影响；
6. URL、邮箱、纯代码输入不出现翻译行；
7. 相同文本第二次输入命中缓存，1.5s 内返回。

### 10.3 AI 回答

1. 点击「AI 回答」后卡片展开，首 token 3s 内出现；
2. 回答流式渲染，面板内部滚动，页面不跳动；
3. 生成中按 Esc / 点击外部，请求中断，不保留半截回答；
4. 回答完成后「复制」「重新生成」「继续追问」可用；
5. 「继续追问」跳转 `/chat` 并预填问题，不把搜索回答当成历史消息；
6. 模型失败时展示重试，不自动重复请求；
7. 搜索 AI 不出现在 `/chat/conversations` 列表中；
8. Enter 仍然打开搜索引擎结果页；`Ctrl/Cmd + Enter` 才触发 AI 回答。

### 10.4 知识库优先

1. 开关默认关闭；关闭时请求不携带知识库检索；
2. 开启且知识库有命中：回答依据知识库，展示引用 chip；
3. 开启且知识库无命中：回答正常返回，顶部标注「知识库未命中，以下为通用回答」；
4. 开启但无已向量化文档：开关置灰并提示；
5. 检索超时 / 异常：回退普通回答，不阻塞；
6. 刷新页面后开关状态保持（本地持久化）；
7. 引用 chip 点击可打开对应知识库文档。

### 10.5 兼容与降级

1. 不改变原有搜索引擎下拉与 Enter 行为；
2. 不改变无壁纸 / 有壁纸两种视觉模式；
3. 窄屏下搜索框与面板不溢出；
4. 增强接口全部失败时，搜索框仍可正常输入和跳转。

## 12. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| 翻译模型延迟高 | 首行翻译慢，用户感知卡 | 1.5s 超时隐藏；轻量模型；缓存 |
| 搜索引擎 suggest 无跨域 / 不稳定 | 远端联想不可用 | 后端代理 + 300ms 超时 + 本地兜底 |
| 全库检索范围过大 | AI 回答慢、引用噪声 | 只取 `is_vectorized=true`，topN + rerank + 阈值 |
| 搜索 AI 污染对话历史 | 会话列表变乱 | 独立 `/search/ai/stream`，不写历史 |
| 用户误以为 AI 回答已联网 | 事实性错误 | 明确标注“AI 生成，未联网核实” |
| 面板遮挡书签区 | 影响导航 | 最大高度 420px，内部滚动，点击外部关闭 |
| 成本失控 | 翻译 / AI 调用过多 | 防抖、缓存、限流、失败不自动重试 |

## 13. 已确认基线与默认值

### 13.1 已确认（2026-11-12）

| 决策点 | 结论 |
|---|---|
| 首行翻译 | 翻译**当前输入内容**，不翻译搜索结果；中英自动互判 |
| Enter 行为 | 保持**直接网页搜索**；AI 回答只由按钮或 `Ctrl/Cmd + Enter` 触发 |
| 知识库优先 | 查**当前账号全部已向量化文档**，不要求用户选择文档集合 |
| 输入联想 | **本期就做**；本地书签 / 历史先返回，远端 suggest 增量补充 |
| 搜索 AI 历史 | 不写入普通对话历史；继续追问才进入 `/chat` |

### 13.2 剩余默认值（不阻塞开发）

| 项 | 本期默认 |
|---|---|
| 翻译语言范围 | 中英互译；其他语言后续扩展 |
| 优先知识库默认状态 | 关闭，用户首次开启后本地记忆 |
| 远端 suggest 失败 | 静默降级为本地联想，不提示错误 |
| AI 回答是否需要反馈按钮 | P1，再做“有用 / 无用” |
